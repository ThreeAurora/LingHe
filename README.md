# 灵鹤 LingHe —— 外挂式智能中文输入法（小鹤音形向）

外挂模式：免安装、免签名、免驱动。整个文件夹拷到任何位置，`python linghe.py` 即用。

> **当前状态（2026-09-09）**：仅 Windows · 码表 19.7 万词条 · 底库 273 万词条 ·
> 端侧统计重排 <5ms · 万象语法搭配查询微秒级 · 可选云端 LLM 终审（DeepSeek，实测
> 266~616ms）· 端侧神经重排 FastReranker 已训练导出（P@1 86.58%），主引擎待接线。
> 性能数字为本机热态实测（RTX 2060 / 消费级 CPU），非通用基准。

## 为什么是外挂而不是安装式

安装式 TSF 输入法需要注册 DLL、测试签名/证书、随系统更新维护兼容性；外挂只需
一个低级键盘钩子 + 自绘候选窗 + Unicode 注入上屏，单目录绿色运行，改代码即改
输入法。对自用工具而言外挂是明显更省事的路线。

## 快速开始

1. **码表**：把 `简单鹤V9.3.0.txt`（或任何 `词条<TAB>编码` 格式的码表）放进
   `mabiao/` 文件夹即可，无需注册。辅助码表（`*辅助*.txt`）同样放这里，自动加载。
   没有码表也能跑（纯底库模式）。
   兜底词库默认已在 `dicts/`（雾凇拼音 + 万象增量，273 万词条），想换就替换该文件夹内容。

2. **配置**：复制模板 `config.example.json` 为 `config.json`，按需修改。
   - `config.json` 已在 `.gitignore` 中（可能含 API key，不入库）；
   - 默认 `ai.enabled=false`、`neural.enabled=false`、`judge.enabled=false`，
     纯本地静态模式即可日用；
   - 想接云端 LLM 终审：填 `judge.api_base / api_key / model`（默认 DeepSeek，
     OpenAI 兼容端点均可），并把 `judge.enabled` 改为 `true`；
   - 万象语法模型（可选）：填 `gram.model` 指向本机 `.gram` 文件。

3. 运行（任选其一）：

```bat
run.bat                                        -- 双击启动（已配好本机 Python 路径）
python linghe.py                               -- 前台运行，看日志
python linghe.py --smoke                       -- 自检（码表/钩子/配置），不常驻
```

> 注意：需要带 tkinter 的 Python（miniconda 自带；嵌入式发行版没有）。核心静态
> 链路零第三方依赖；只有启用神经重排时才需要 `numpy` + `onnxruntime`。

4. 打字：
   - 正常敲小鹤音形码，已背熟的字按码表固频出现在候选前部（通常就是首选）；
   - 码表无命中时，底库 / 整句 / 云端候选顶上来（候选窗短暂显示 … = 云端思考中）；
   - `空格`或`1`=上屏首选；`;`=2选；`'`=3选；`1~9`=选字；`退格`=删码；`Esc`=清码；`组码中按标点`=上屏首选后标点照常；
   - `回车`=上屏已敲的英文字母本身（打英文单词不用先切英文）；
   - `Shift 单击`（400ms 内按下抬起）：**组码中=上屏已敲的英文**；空码时=中/英全局切换（闪 `[中]`/`[EN]`）。
     **英文模式=纯英文直通**：字母/数字/标点全透传，无候选窗、无组码、无任何 UI；
   - `=`/`Tab`=候选下一页（末页回卷），`-`=上一页；候选池 90 个，每页 9 个；
   - **上屏联想**：每次上屏后自动提示下一个可能的词（豆包式），`空格`直接上屏联想词
     并继续联想成链；敲其他任意键联想消失，不打扰正常组码；
   - `Ctrl+Alt+L`=暂停/恢复外挂；
   - **不会自动上屏四码**：第 5 码起继续当纯双拼音节，六码可打「詹姆斯」
     （vjmusi），更长的整句走声母简拼（见下文「简拼」）；缓冲区默认最长
     14 键（`max_buffer_len` 可调）。

## 智能候选链路

一次击键到候选窗刷新，走五层（由快到慢）：

```
击键 → ① 检索召回    码表固频 + 底库双索引 + Viterbi 整句 + 锚点/贪心/口语字链
     → ② 万象语法    上下文搭配证据，微秒级，给动态候选减价浮顶
     → ③ 统计重排    词频 + 用户个性化 + 长词奖励 + 上文 bigram，<5ms
     → ④ 云端终审    DeepSeek 异步生成/判别（可选，266~616ms 到达）
     → ⑤ 神经重排    FastReranker ONNX（已训练导出，主引擎待接线）
```

| 层 | 实现 | 状态 |
|---|---|---|
| ① 检索召回 | `mabiao.py` / `dict_engine.py` / `rerank.py` | 常开 |
| ② 万象语法 | `gram_model.py` + `linghe.py` 减价/压顶 | 需自备 `.gram` 模型，缺失自动跳过 |
| ③ 统计重排 | `rerank.py` StatReranker | 常开 |
| ④ 云端终审 | `cloud_judge.py`（DeepSeek） | 配置 key 后启用 |
| ⑤ 神经重排 | `fast_rerank.py` + `train/ckpt/reranker.onnx` | 模型就绪，待接线 |

## 候选排序公式（核心约定）

```
候选池（90 个，每页 9 个）
  = [ 辅助码筛选命中 ]            ← 最高优先，直接顶到首选（作用于码表+底库全部词）
  ++ [ 辅码逐字锁定组词 ]          ← 词库外词也能组出来（xlgmko→象鸣）
  ++ [ 码表侧(固频序) 精确码 + 前缀命中 ]   ← 主码表固定调频，永不重排
  ++ [ 底库词（动态调频：统计重排 + 万象语法减价）]
  ++ [ Viterbi 整句切分（第 5 码起，全拼/简拼两路按每字代价合并）]
  ++ [ 云端生成首选（简拼整句直接写答案，异步压顶动态区）]
```

**码表是固频的（背熟的字按码表行序，永不重排）；底库是动态调频的**——统计重排
只作用于底库候选。重排模型：`词频(unigram, 底库真实词频) + 用户个性化(上屏次数)
+ 长词奖励/单字惩罚 + 上文 bigram(在线学习)`，参数由 `tune.py` 在真实用例上扫参
定案（L=12/P=4，全拼整句 10 例命中 9）。

万象语法在统计分之上做减价：`GRAM_ALPHA(0.25) × min(GRAM_MAX, ev)`，有上下文证据的
动态候选浮顶；`GRAM_TOP_EV(6.0)` 是压顶闸——证据不够就不压固频区，肌肉记忆优先。

静态侧（码表前缀索引 + 底库双索引）实测码表 0.005~0.04ms、底库亚毫秒——
「0.1 秒出词」由它们保证；整句切分（Viterbi beam）单次 1~3ms 本地出整句；
云端 LLM 只在简拼整句 / 长码异步补位，`config.json` 里 `ai.enabled=false`（默认）
可整体停用 LLM 兜底。

## 万象语法模型（gram_model.py）

2026-09-07 接线、09-09 入库的搭配证据层。直接 mmap 读取 Rime 的 `.gram` 二进制
（`Rime::Grammar/1.0` + Darts-clone 双数组），不依赖任何 Rime 框架，查询微秒级：

- `gram.query(context, word, is_rear=False)` 返回搭配对数概率；
  `NC_PEN = -12.0` 是无证据基准，`ev = 分 - NC_PEN`；
- **多窗口上下文**：只认尾缀搭配会漏证据（「蘑菇→孢子」被中间词「喷出了」截断），
  改为 `gwin = [尾词] + 上文最近 3 词` 逐窗取最大 `ev`；
- **音节守卫**：只给「词库真词 + 音节数匹配」的动态候选压顶，挡掉 Viterbi 拼字伪句
  与异长词蹭证据；
- **句内尾词证据**：长整句候选用句内前词单独确证尾词（`蘑菇喷出了|孢子`），封顶放宽 2×；
- 实测：`bczi`（上文「蘑菇喷出了」）→ 孢子第 1；`mogupfiulebczi` → 蘑菇喷出了孢子第 1。

模型文件（GB 级）不入库，路径在 `config.json` 的 `gram.model` 指定；没有模型时
该层自动跳过，不影响其余功能。

## 辅助码（手心辅助码）

把 `*辅助*.txt`（如 `简单鹤V9.3.0电脑手心辅助码.txt`）和码表一起放进 `mabiao/`，
自动加载（实测 9980 行，覆盖 8400 字）。**每个字的辅助码只取首键**筛选。

一个键串会被 `parser.py` 同时按四种确定形态解析，命中即并集输出：

| 形态 | 触发 | 例 |
|---|---|---|
| 纯音节 | 偶数长 | `yiyi` → 意义/异议… |
| 词尾单辅助码 | 奇数长（≥3） | `yiyit` → 异议（t=异的辅码，表「任意字」） |
| 全辅助码 6 码 | 长度 3 的倍数 | `yityic` → 异议（t=异，c=议，逐字定位） |
| 首字辅码 | 奇数长（≥5） | `yicui` → 意识（c=意 的辅码，紧跟首音节） |

规则要点：辅助码可以加在**词尾**、**每个字都加**（凑成 6 码），或**首字后紧跟
一码**（首字辅码）；不允许中间穿插半个。筛选后仍有多个候选时，按码表原顺序
（固频）排列。打词时**任意**一个字的辅助码都能把该词筛到首选。

**辅码逐字锁定组词**（2026-09-07 新增）：每个音节都有本字辅码时，字身份已被
唯一确定，于是词库里没有的词也能直接组出来——`xlgmko` → 象鸣（象鸣不在任何
词表，xl+g / mk+o 已锁定）。全锁定组词尾随码表/底库真词之后进固频区；选中上屏
即自动造词入库，下次直接命中。

## 兜底底库（dicts/）

码表之下挂了一个大词库作为底座，来源 GitHub 开源项目 **rime-ice/雾凇拼音**，
另加万象增量与热词增量：

| 文件 | 规模 | 说明 |
|---|---|---|
| `base.dict.yaml` | 543092 词条 | 通用词库，自带拼音 |
| `tencent.dict.yaml` | 980968 词条 | 三字以上词/网络流行语，**无拼音**，靠 `char_pinyin.txt` 逐字自动注音 |
| `wanxiang_inc.dict.yaml` | 48.8MB | 万象增量词库（`convert_wanxiang.py` 转换） |
| `hotwords_inc.dict.yaml` | 热词增量 | `fetch_hotwords.py` 定期注入 |
| `char_pinyin.txt` | 44437 字 | 汉字→拼音全表（mozillazg/pinyin-data） |
| `spoken_freq.txt` + `spoken_2gram/3gram.txt` | 283486 词 | 口语词频与 2/3gram（口语字链召回） |
| `cooc_pre.bin` | 词 1990845 / 字 199238 | SIGHAN 预训练共现表（`build_cooc.py` 可复现） |

合计 **2731823 词条**（启动日志实测，含万象/热词增量），双索引：全拼
`zhan mu si`→詹姆斯、声母简拼 `u v u`→深圳市。词库文本随仓库分发；二进制
缓存与 `lexicon.db` 不入库，首次运行自动重建。

**两段式加载**（2026-09-07 起）：先装 20 万高频词 mini 索引（缓存后 2~9s）即可
打字，全量 273 万词后台热切换（全量缓存加载约 44s，期间输入法已可用）。
之后走 marshal 二进制缓存（`dicts/.cache.bin` / `.cache_mini.bin`，按词库文件
签名自动失效）；**首次无缓存时需重新解析词库文本**，比缓存加载慢（后台线程，
期间输入法已可用）。

**自动记忆**：每次上屏都会把「词 + 拼音」写入 `dicts/user_dict.txt`（词频累加），
下次起该词按使用次数优先出现。新词/网络词打过一次就记住，无需手工加词。
同时学习相邻词共现（`dicts/user_bigram.txt`），重排与整句切分随使用越来越准。
退出时自动落盘（每 30 次上屏批量合并写一次，不碰击键路径）。

## 简拼（整句声母）

第 5 码起若不是规整双拼，就当**整句声母简拼**处理：每键取一个字的声母
（zh/ch/sh 记作 v/i/u）。例如 `wilygbz` → 我吃了一个包子。**2 键起就放宽召回**
（`bz` → 包子，2 键也走全池不截断），不再等到打满。

这条路径由四层共同承担（由快到慢）：
1. **底库简拼索引**：声母串恰是整词的（如 `u v u`→深圳市），亚毫秒即时命中；
2. **Viterbi 统计整句切分**：把声母/音节流切成词序列，本地 1~3ms 出整句
   （全拼整句 10 例命中 9：我吃了一个包子/今天天气不错/我们一起去吃饭…）。
   打分 = 词频 + 用户个性化 + 上文 bigram（在线学习 + **SIGHAN 预训练共现表**，
   词级 199 万对/字级 19.9 万对，开箱即有语言常识）；简拼冷启动仍受 unigram
   歧义限制，但**越用越准**——上屏自动学习 bigram 共现，打过一次下次就对；
3. **云端生成首选**：简拼整句信息不足时统计层猜不准，云端大模型直接生成
   用户最可能想打的整句（豆包式，`wjtxixhcy → 我今天想吃西湖醋鱼` 首选），
   异步到达、压顶动态区，不阻塞击键；
4. **AI 异步精修**：整句场景有天然停顿（打完一串键才看结果），AI 数百 ms
   的结果能赶上，按（上下文+键码）缓存。

## 云端裁判（DeepSeek）

`judge.enabled=true` 且配置了 `judge.api_key` 时，终审裁判升级为**云端大模型**
（默认 DeepSeek，OpenAI 兼容端点；2026-09-08 由火山豆包切换而来）。两者缺一都不会
走云端：没有 key 时回落本地 Qwen 判别裁判（需自备模型目录），
`judge.enabled=false` 则整层停用：

- **生成通道**：只给「上文 + 键入码」，云端直接写用户最可能想打的 1~3 个候选
  ——简拼整句首选（`wjtxixhcy → 我今天想吃西湖醋鱼`）只靠生成，不需要这句话
  存在于任何词表；结果异步压顶动态区（码表固频区永不被动）。
- **判别式排序通道**：对本地召回候选做语义级重排（候选池里挑最可能），
  与生成通道并存（`max_cand` 控制名单长度）。
- **音形校验**：云端结果先过音形校验，音形不符的直接丢弃（日志可见
  `[云端校验] 丢弃音形不符: …`），只留能对号入座的候选，零幻觉。
- **工程**：异步单 worker + 只留最新请求（连击不排队）；结果按（上文, 码）缓存；
  失败/超时连续 3 次自降级回本地 Qwen2.5-0.5B 判别裁判，永不卡击键。
- **实测**（本机日志，无缓存命中）：`bz → 包子` 602ms、`bczi → 宝姿` 394ms、
  `nhwujd → 你好我是经典` 616ms、`qrzids → 全自动` 460ms、`wxvdv → 我想找到这` 266ms。

`config.json` 的 `judge` 段：`api_base`（默认 `https://api.deepseek.com`）、
`api_key` / `model`、`timeout` / `max_cand`。不配置 `api_key` → 自动回落本地
Qwen2.5-0.5B 判别裁判（模型目录 `judge.model_dir`，不入库，`fetch_qwen.py` 可再生）。

## 关于「0.1 秒内 AI 调频」：豆包是怎么做到的

先说结论：**LLM 生成式推理做不到，API 只会更慢。** 这不是工程优化问题，是物理限制。

- 自回归生成必须逐 token 串行解码，1.5B 模型 CPU 上热调用也要 0.22~0.3s；
- 走 API 还要叠加网络 RTT + 排队 + 更长的前缀处理，实测必然慢于本地；
  **API 的价值是模型更强（准），不是更快**。

豆包输入法那种「明显有 AI 又 <0.1s」的真实架构是**双层**：

```
第一层（<1ms）：   Trie/词表候选生成 —— 拼音切分、词典召回，产出 50~200 个候选
                   ↑ 这一层保证「0.1 秒出词」，本质是检索不是生成
第二层（5~30ms）： 端侧判别式重排模型（小 BERT / 双塔，几十 MB）
                   —— 输入 (上下文, 候选) 打分，只做一次前向传播，不生成 token
                   ↑ 这一层提供「太智能了刚好是我要的词」的体感
```

关键差异：重排是**判别**（对已有候选打分，一次前向，可批处理、可端侧跑），
生成是**自回归**（必须一个字一个字吐，串行不可并行）。所以「AI 调频」的
正确姿势是「检索召回 + 判别式重排」，而不是「让 LLM 当场造句」。

灵鹤当前的对应实现与差距：
- 第一层已具备（码表前缀索引 + 底库双索引 + 万象语法，共 273 万级词条）；
- **第二层已落地为端侧统计判别式重排**（`rerank.py`，零依赖 <5ms）：
  词频 unigram + 用户个性化 + 长词奖励/单字惩罚 + 上文 bigram（在线学习 +
  SIGHAN 预训练共现），对召回候选统一打分——这就是「检索召回 + 判别式重排」
  路线的可运行版本；
- **神经版第二层已训练就绪**：FastReranker v4 P@1 86.58%，11.4MB ONNX，
  接线后替换统计打分即可，架构不用动；
- LLM 退居「生僻长句异步兜底」（只补静态侧没打满的空位，不参与同步调频）。

## 上屏联想（豆包式）

每次上屏后，候选窗立刻变成 `[已上屏词 + 联想词]`，空格直接上屏联想词并继续
联想下一环，一串常用搭配（如 上班→打卡、卫生间→纸）空格连按即可，全程 0 键入。
实现：`rerank.next_word()` —— 用户共现表（B 权重）与预训练共现表（B_PRE 权重）
的后继倒排索引取强者，只推荐底库存在的词（不推生僻人名），均延迟 1.3ms。
敲其他任意键联想消失。

## AI 预测（默认关闭）

`ai.enabled=false` 是当前默认——LLM 生成式预测已退居可选增强，不参与主链路。
想启用（本机 Ollama / LM Studio / 任何 OpenAI 兼容端点）：

- 每次组码异步发起预测（只保留最新请求，继续打字自动作废旧请求，不卡手）；
- 上下文 = 本外挂自己上屏的历史文本（切窗口自动清空），连同键入码的拼音解读
  （4 码给「单字音形」+「二字词」两种解读；>4 码给「多音节词」+「整句声母简拼」）
  一起喂给模型；
- 模型只要求输出 JSON 候选数组；结果按（上下文+键码）缓存；
- AI 未就绪/超时时自动降级为纯码表模式，按键永不阻塞。

## 已知限制

- **仅 Windows**：依赖 Win32 低级键盘钩子 / Unicode 注入 / UI caret，未做跨平台；
- 管理员权限窗口里钩子失效（UIPI 限制），需要时以管理员身份运行本程序；
- 上屏用 Unicode 注入，对极少数 DirectInput 游戏/密码控件无效；
- 候选窗跟随光标（UI caret），个别自绘光标应用回退到鼠标位置；
- 无托盘图标（后续加）；UI 是刻意简陋的；
- 底库全量加载约 44s（marshal 缓存后）；轻量索引 20 万词 2~9s 即可打字，
  全量后台热切换不阻塞；
- 简拼冷启动有 unigram 歧义上限（wilygbz 类短串可能出次优解），
  多层兜底：检索 → 统计整句 → 云端生成 → AI 异步精修，且越用越准；
- 万象语法需要自备 `.gram` 模型（GB 级，不入库）；
- FastReranker 已训练导出但**尚未接线**，当前不参与排序；
- LLM 只做异步兜底，不做同步调频——同步调频由端侧统计判别重排承担（<5ms）。
